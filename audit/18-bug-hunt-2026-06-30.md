# LabDesk — Adversarial Multi-Agent Bug Hunt (2026-06-30)

> Generated by a 103-agent workflow: 8 area finders → 2 adversarial skeptics per finding
> (refute + reproduce/impact) → synthesis. 47 candidates → **25 confirmed**, 8 uncertain, 14 rejected.
> Only issues both reviewers independently agreed were real are listed as Confirmed.

# LabDesk Code Audit — Reviewer Synthesis

Severity reflects real-world impact after adversarial verification. All CONFIRMED issues were independently agreed real by two reviewers.

## Confirmed — High

### 1. Outstanding-Dues "Mark selected as paid" crashes every time
`src/labdesk/presentation/accounts.py:348`
`db.receive_due(self.con, rid, amount, self.user["username"])` omits the required keyword-only `actor_role`, so Python raises `TypeError` before any work. The Accounts dues-recovery feature is completely non-functional (the parallel call in `receipts_mutations.py:56` passes it correctly). No data loss — it aborts before any write.
**Fix:** `db.receive_due(self.con, rid, amount, self.user["username"], actor_role=self.user["role"])`.

### 2. Period income is dated to bill creation, not when cash was collected
`src/labdesk/presentation/accounts.py:131-159`
Income and per-method collection are computed as `SUM(MIN(paid,net_amount))` keyed on `date(received_at)`, but `paid` is a mutable snapshot later changed by due-recovery, edits, and voids. Collecting an old due today retroactively inflates the original bill's month; voiding an old paid bill erases income from an already-closed period. The date-correct `ledger` table (with proper event dates) is written on every cash event but never `SELECT`ed anywhere — it is dead data.
**Fix:** Compute period income and the by-method breakdown from the `ledger` (credit/debit by `date`), not from the `receipts.paid` snapshot.

### 3. Verification code (HMAC) ignores the printed Impression/Conclusion and Remarks
`src/labdesk/report/verify.py:54-83`
`report_fingerprint()` covers receipt identity, results, and cultures, but never `receipt_items.conclusion` or `receipt_items.remarks` — both printed prominently and rendered by `render/report_doc.py` (`_draw_conclusion`, `_draw_blocks_after_table`). For imaging/serology/molecular reports the impression *is* the clinical payload, yet altering it leaves the recomputed "Verification code" unchanged, defeating the anti-tamper guarantee.
**Fix:** Add per-item `conclusion` and `remarks` (ordered by `ri.id`) to the fingerprint.

### 4. Catalog re-seed matches by autoincrement id → shipped tests silently dropped / partial
`src/labdesk/db/connection.py:370-387`
`_sync_catalog_from_seed` inserts new rows `WHERE id NOT IN (SELECT id FROM tests)` (same for `test_parameters`). Both ids are AUTOINCREMENT and the live DB mints its own ids when a lab adds custom tests. A later seed's new rows reuse those id ranges, so the additive insert skips them. A new test can be inserted while some of its parameters collide and are dropped, yielding a broken parameter set. `catalog_version` is then bumped unconditionally, so the sync never retries — missing data is permanent. Affects exactly the labs that customize their catalog.
**Fix:** Match seed rows by a stable natural key (e.g. `legacy_no`/`seed_uid`), insert parameters relative to the actually-inserted parent, and only bump `catalog_version` after confirming the rows landed.

### 5. Culture-only receipt: "Save results" finalizes it with no data entered
`src/labdesk/presentation/worklist.py:788`
For a culture-only receipt, `result_rows` is empty, so the blank-save guard (`if result_rows and not _has_enterable_content(...)`) is skipped, and `release_results` still runs `UPDATE receipts SET status='reported' …`. This freezes the bill, locks editing to admins, and — if `whatsapp_auto='1'` — auto-sends an empty report. Cultures are meant to be entered later on the Microbiology screen.
**Fix:** Bail out before `release_results` when there is genuinely nothing to persist, or only stamp `reported` when at least one result/remark/conclusion was written.

## Confirmed — Medium

### 6. Receipts list financial totals silently truncated at LIMIT 1000
`src/labdesk/presentation/receipts.py:288`
The footer Net/Paid/Due sums only the fetched rows, capped at `LIMIT 1000`. The default view is "All status / no date filter," so any lab with >1000 receipts sees understated totals presented as complete (and "Showing 1000 receipt(s)" hides it). CSV export inherits the same truncation.
**Fix:** Compute totals/count with a separate aggregate query (no LIMIT), re-query for export, and flag when display is capped ("Showing first 1000 of N").

### 7. Table rows can overprint the footer/signatures
`src/labdesk/render/report_doc.py:352` (repeated at 689, 847, 1005)
`body_bottom = 297 - 8 - 27 + 24 = 286mm` — the `+24` fudge reclaims most of the reserved `REPORT_FOOTER_MM` band. On a page where a table fills to the bottom, the last rows overlap the signatory/disclaimer block; the footer-wrap change worsens it. Deterministic on full overflow pages of an official medical document.
**Fix:** Compute `body_bottom` from the actual footer height for the report (signatures present? wrapped disclaimer?) instead of a fixed `+24`.

### 8. Corrupt existing DB: the only documented recovery path is unreachable
`src/labdesk/app.py:536-545`
On `init_db()` failure for an existing DB, `_db_damaged_notice` tells the user to use "Settings → Backup & restore → Restore from file…", but that lives inside `MainWindow`, which is never built on this path (restore dialog is gated on first-run `if not dbf.exists()`). Every relaunch dead-ends with the same notice; the only real escape is manually deleting the DB file. Availability/recoverability defect with actively misleading guidance.
**Fix:** On `init_db` failure for an existing DB, offer `RestoreBackupDialog` (or a dedicated recovery dialog) directly.

### 9. Manager discount approval authorizes "a discount," not an amount
`src/labdesk/presentation/reception.py:375-379, 453-461`
Approval only sets a boolean flag and unlocks the spinbox; the save guard checks the flag is non-None but never compares the current discount to what the manager approved. A cashier can have a manager unlock the field (showing 0%), then type up to 100% and save. Mitigated by required manager presence and an audit trail (`discount_approved_by`).
**Fix:** Capture the approved value at approval time and reject at save when the discount exceeds it (plus promo); or set the discount inside the approval dialog and lock the spinbox to it.

### 10. Returning-patient search hides distinct patients who share a phone number
`src/labdesk/presentation/reception_patient.py:32-41`
The dedup subquery `GROUP BY COALESCE(NULLIF(telephone,''), mr_no, id)` keyed on phone collapses family members sharing one number to a single `MAX(id)` row. Searching that phone (or a shared surname) returns only the latest registrant; the rest are hidden, causing duplicate records and fragmented history. Patient rows are not duplicated per visit, so the dedup is largely unneeded.
**Fix:** Key the dedup on patient identity (`id`), or include name in the group key.

### 11. Auto-matched returning patient can have its permanent MR overwritten
`src/labdesk/application/receipts.py:65`
On the phone+name auto-match path, a resolved `pid` is passed as `existing_patient_id` while the typed `mr_no` is also forwarded; `_upsert_patient` does `mr_no = mr_no or …`, so a typed value wins over the stored permanent MR and the UPDATE rewrites it. Silent corruption of the canonical identifier; gated behind a non-default operator action and the check-letter validator (which only catches the new dashed format).
**Fix:** For returning/auto-matched patients prefer the stored `mr_no` over the typed one, or only write `mr_no` when inserting a new patient.

### 12. "Test connection" runs blocking HTTP on the UI thread
`src/labdesk/presentation/settings_whatsapp.py:84-93`
`_test_whatsapp()` calls `whatsapp.check_status()` synchronously — a blocking GET with an 8s timeout. If the gateway is down/slow the window freezes for up to 8s with no busy indicator, unlike the sibling `_send_test_whatsapp()` which uses `tasks.run_in_background`.
**Fix:** Route through `tasks.run_in_background` with a "Checking…" busy state and update status in the done callback.

### 13. Auto-send-on-results spams red error toasts for normal skips
`src/labdesk/presentation/worklist.py:821-834`
With `whatsapp_auto` on, saving results calls `wa.send_async` unconditionally; its `config_ready`/`recipient_ready` pre-checks emit a red warning toast for opted-out patients, missing numbers, or unconfigured gateway — turning expected skips into nagging errors. The receipt path (`reception.py:574-579`) deliberately gates silently first.
**Fix:** Only call `send_async` when `config_ready(c)[0]` and `recipient_ready(c, rid)[0]` are both true.

### 14. WhatsApp country code is unvalidated → every send fails, blaming the patient
`src/labdesk/presentation/settings_fields.py:44-55`
`whatsapp_country_code` is length-capped but not in `NUMERIC_FIELDS` and has no validator, so an admin can save `+92`/`9 2`. `wa_number` then rejects every recipient (`num.isdigit()` fails) and surfaces "This patient has no valid WhatsApp number," misdirecting the receptionist to patient phones while the real fault is one global setting. (A purely-numeric-but-wrong code instead silently mis-sends.)
**Fix:** Validate/sanitize the country code on save (strip to digits / reject non-digits), and normalize it in `wa_number`.

### 15. Restore validation breaks on backup paths containing `?` or `#`
`src/labdesk/db/backup.py:157`
`sqlite3.connect(f"file:{path}?mode=ro", uri=True)` parses the user-picked path as a URI, so a folder/file named e.g. `Lab #1` is truncated; the probe opens the wrong/empty target and a valid backup becomes un-restorable (with a misleading "couldn't open with that password" on the unlock path). `#` is a common, legal folder character on Linux/macOS.
**Fix:** Open the plain path without URI interpolation, or build the URI via `Path(path).as_uri()` + `?mode=ro`.

## Confirmed — Low

### 16. Brute-force failure counter is a lost-update race
`src/labdesk/db/auth.py:99-113`
`verify_user()` reads `failed_attempts`, computes `+1` in Python, and writes a literal value — non-atomic across the multi-instance shared-DB use the app explicitly supports, so concurrent wrong-password attempts drop increments. Only slows the counter (lockout still eventually fires); attacker is already past SQLCipher.
**Fix:** `UPDATE users SET failed_attempts = COALESCE(failed_attempts,0)+1 …`, then re-select to compute the lock window.

### 17. Expense audit log shows the default currency symbol
`src/labdesk/presentation/accounts.py:259`
`money(amount)` is called with no currency arg, so a lab with a non-default currency records the wrong symbol in the financial audit string (same omission at line 340). Amount is correct; cosmetic.
**Fix:** Pass `money(amount, db.currency(self.con))`.

### 18. Inconsistent "Page X of Y" when a test overflows pages
`src/labdesk/render/report_doc.py:1430-1441`
`total_pages` is fixed at one-per-test; overflow footers use `total_pages+1` ("will fix total below" — never fixed) while final footers use `max(total_pages, page_no)`, yielding mismatched denominators (e.g. "1 of 3", "2 of 2", "3 of 3"). Cosmetic, rare.
**Fix:** Pre-compute the true page count (paginate once on a throwaway doc) and pass it to every footer.

### 19. After save, the right-hand panel still shows a now-locked report as editable
`src/labdesk/presentation/worklist.py:835`
`save_results` only calls `refresh_list()` (left table); the lock banner / read-only logic lives in `load_receipt`, which isn't re-invoked. A non-admin keeps typing until the next save is rejected. Server-side lock still enforced — no data risk.
**Fix:** Re-run `load_receipt()` (or re-apply the lock state) after a successful save.

### 20. Patient "name required" accepts digit/punctuation-only input
`src/labdesk/presentation/reception.py:441-446`
`format_person_name` leaves non-letter tokens unchanged, so `123` or `!!!` pass the emptiness-only guard and a receipt/report can be created with a letter-free name. Data-quality only.
**Fix:** Reject when the formatted name contains no letter (`re.search(r'[^\W\d_]', name) is None`).

### 21. WhatsApp timeout: UI accepts 1–600s but runtime clamps to 5–120s
`src/labdesk/presentation/settings_fields.py:106-111`
The field validates/saves 1–600, but `whatsapp._cfg()` does `max(5, min(timeout, 120))`, so a saved 300 silently becomes 120. Misleading for anyone tuning for slow links/large PDFs.
**Fix:** Make the declared range, validator, hint, and clamp agree.

### 22. Splash is closed before the catalog sync it documents
`src/labdesk/app.py:460-461`
The splash (whose comment says it covers "the one-time catalog sync after an update, ~1s") is closed before `init_db()` runs that sync and never re-shown, so the ~1s post-update sync shows no feedback. Cosmetic.
**Fix:** Re-show a small "Updating…" indicator around `db.init_db()`, or drop the misleading comment.

### 23. "Already running, brought to the front" reported before any window exists
`src/labdesk/app.py:398-411`
The activation socket `listen()`s immediately but the notifier that raises the window is installed only after login. A second launch's `connect()` succeeds into the backlog regardless, so the user is told the window was raised while the primary still sits at the login/unlock dialog. Cosmetic message inaccuracy.
**Fix:** Have the primary send an ack only once the listener+window are live, and require that ack before claiming the window was raised.

### 24. WhatsApp access token displayed in plaintext
`src/labdesk/presentation/settings.py:169-181`
The token is deliberately stored as a 0600 secret outside the DB, but its Settings field is a normal visible `QLineEdit` populated in cleartext (unlike the password field, which uses `QLineEdit.Password`). Shoulder-surf / screenshot exposure on an admin-only page.
**Fix:** Set `echoMode=QLineEdit.Password` (with an optional reveal toggle) for `whatsapp_api_key`.

## Confirmed — Nit

### 25. Hand-typed Patient ID stored in original case
`src/labdesk/presentation/reception.py:464, 516-541`
`validate_patient_id` uppercases internally to check the letter, but the raw text is saved, so the table can hold mixed-case `mr_no` for the same canonical id. All lookups are case-insensitive `LIKE`, so impact is purely cosmetic.
**Fix:** Uppercase to canonical form after successful validation before saving.

## Uncertain / needs human judgement

- **Login timing-equalisation leaks for legacy-sha256 accounts / first unknown-user probe** (`db/crypto.py:56-62`) — the scrypt dummy doesn't match the fast sha256 path of un-upgraded legacy accounts, re-enabling username-enumeration timing. Real at code level; practically irrelevant for a local desktop app with no network auth endpoint. *Build the dummy at import; match the stored hash scheme (or force-upgrade legacy hashes).*
- **Disk fingerprint can flip when a USB drive enumerates as `sda`** (`licensing/fingerprint.py:78-95`) — only causes a spurious `wrong_machine` lockout if a second signal also changed; self-heals on unplug; needs a narrow stack-up (SATA internal as `sdb`, serial-exposing USB). *Prefer non-removable devices (`/sys/block/<dev>/removable`).*
- **Missing service-layer `require()` for money/settings writes** (`accounts.py:222` add_expense; `settings.py:397-466` save) — both write money/settings/audit behind UI visibility only, diverging from the documented defence-in-depth model. Latent today: no level-4 role exists and `PAGE_MIN_LEVEL == CAP_MIN_LEVEL` for these, so only admins reach them. *Add the corresponding `roles.require(...)` to keep the model uniform.*
- **Descriptive param whose name contains "conclusion"/"impression" is dropped from the grid** (`worklist.py:528`) — reviewers split on whether data is lost; the save path is upsert-only (no blanket delete), so existing values persist, but such a param gets no editor. Narrow, admin-created. *Match the conclusion param by exact name / designated row.*
- **Orphan `results` rows for culture items** (`worklist.py:842`) — `_static_line_rows` doesn't skip culture items; can write dead rows if a culture test has L/H/unnamed params. Not reachable with the shipped catalog; zero render impact. *Skip culture items in static-row generation.*
- **Check-letter validation skipped for dash-less new-format IDs** (`reception.py:467-472`) — guard requires `"-" in mr_no`; `2600043K` bypasses it. `mr_no` is a free-text label, not a linkage key, so impact is a slightly-wrong label. *Normalize/insert dashes before deciding to validate.*
- **`LABDESK_NO_AUTOSCALE` uses bare truthiness** (`app.py:340-342`) — `=0` disables auto-scale, inconsistent with the sibling `== "1"`. Undocumented var; cosmetic. *Treat as an explicit boolean.*

## Top priorities
1. **Fix the dues-recovery crash (#1)** — one-line change; the feature is 100% broken today.
2. **Correct period income to use the `ledger` by event date (#2)** — monthly income/cash reconciliation is currently wrong for any lab that collects dues, edits, or voids across months.
3. **Fix the catalog re-seed id-collision (#4)** — silent, permanent loss of shipped tests/parameters after updates, hitting your most engaged (customizing) labs.
4. **Include impression/remarks in the verification HMAC (#3)** and **stop culture-only saves from auto-finalizing/auto-sending empty reports (#5)** — both undermine trust in finalized medical reports.
